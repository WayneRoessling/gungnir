| D-10 Repository hosting, runners, registry, vulnerability response | **Amended 2026-09-08: the `gpu` runner exists, and `gpu-fusion.yml` stays on `workflow_dispatch` permanently.** The runner the 2026-09-07 amendment said this workflow still needed is registered: `gungnir-rtx-5060ti`, labels `self-hosted, Windows, X64, gpu`, on the owner's workstation and its NVIDIA RTX 5060 Ti. **The trigger is not restored with it, and that is a decision rather than a wait.** A `workflow_dispatch` job on a self-hosted runner already *is* local execution -- the compute happens on the owner's hardware, and GitHub contributes the trigger and the log -- and dispatch can only be fired by a caller with write access, so no fork's pull request can reach the machine. A `pull_request` trigger would reverse exactly that: this repository is public, the runner is a workstation, and GitHub's own guidance is against the pairing. The cost accepted is that each GPU validation run is fired by hand (`gh workflow run gpu-fusion.yml`), which is a trivial cadence for a path that changes rarely. The alternative considered and declined was dropping the workflow and running `cargo test -p gungnir-data-fusion --features gpu-tests -- --ignored` on the host: it is the same command and the same hardware, but it produces no CI log, and `../../release-governance.md` defines the evidence package as the logs of every gate that ran, assembled by nobody. | D-22 Cipher and test-certificate crates | **Raised by GAP-060, which could not start without it.** DN-22 designs a custody boundary and names no algorithm; `seal` and `unseal` need an authenticated cipher, and none is in the workspace. Recommended: `aes-gcm` (AES-256-GCM, FIPS-approved and hardware-accelerated on both targets) and `rcgen` in `[dev-dependencies]` only.   need it removed first. Forking was rejected: the graph refuses git
  dependencies, so a fork means vendoring, and owning a font parser with no upstream is
  a larger accreditation question than the advisory it would close.
  **The three vulnerabilities followed the same day.** `vtkio` 0.6.3's XML reader
  (quick-xml 0.22: RUSTSEC-2026-0194 and -0195) and its appended-data codecs (lz4_flex
  0.7: RUSTSEC-2026-0041) have no patched upstream, since even the 0.7.0 candidates pin
  quick-xml 0.36 against a fix in 0.41, and a VTK file is operator-supplied input on the
  node. Both features are compiled out: only legacy `.vtk` loads, `gungnir-data` refuses
  an XML extension naming the reason, a test holds that wording, and the workspace
  `Cargo.toml` says what restores them. GAP-023's "legacy and XML" therefore narrowed to
  legacy on 2026-09-07; the XML half is owed to a vtkio release, not to this project.
  The remaining quick-xml (0.30, under `accesskit_unix`, the Linux AT-SPI bridge) exists
  only in `gungnir-app` compiled for Linux, which no release builds; its two advisory ids
  are ignored in `deny.toml` with that reason and with the caveat that an id-level
  ignore would also mask a new pre-0.41 quick-xml, which the ignore's own match report
  is the check for. With those two ignores, `cargo deny check` passes all four checks
  for the first time.
