## 1. Summary

**Design B+, code B-, operator-facing C, validation absent.** The previous review's C stands
for what an operator lives in, and the reasons are now filed as five open gaps rather than
prose. What has changed in four days is real: the weapons control status is live from the
strip (GAP-203), the track table is virtualised and the egui gate measures the workspace
that holds it at Scenario 4's count (GAP-226), the three-d scene has been looked at by a
person (D-153), a rehearsal's empty queue no longer blames the picture (GAP-250), and the
terrain dead spots, the per-laydown field and the one-sensor what-if all reached the map and
the planning panel (GAP-246 to GAP-249). The code that landed follows the standards it cites.

What this review adds, having run the desktop and read the hot path, is a set of defects
the headless tests cannot see:

- **The default renderer shows less than the opt-out.** In the three-d scene a track is a
  filled disc: no identifier, no classification frame, no heading vector, no uncertainty
  outline, no assignment tag. All of those are drawn only by the projection, and the scene's
  own status line reports "1 assignments" while drawing none. The owner's record says this
  plainly; the setting is still on by default.
- **Two per-frame GPU and CPU rebuilds that §5 forbids**: the glyph instance buffers are
  re-created on the GPU every frame whether or not a track moved, and the terrain surface is
  re-tessellated from the DEM every frame. Neither is inside any budget test: the egui gate
  times the dock tree only.
- **The replay panel's session picker is never filled when docked.** Only the detached
  path reads the journal directory; the dock tree draws PN-12 with an empty list. Every
  analyst, planner and administrator layout docks it.
- **A detached window cannot be closed**, and the evidence card and both decision dialogs
  open over the status strip, which the information architecture says is always visible.
- **Escape closes nothing, Tab shows nothing, and Enter on a focused Accept is a
  decision.** The dialogs' comment says no control is bound to Enter; egui binds Enter and
  Space to any focused button, and `clicked()` includes that activation.
- **The alert list grows for the life of the session** with nothing removed, no scroll
  area and no acknowledgement; on screen it was nine "expired with nobody deciding" lines
  within four minutes of a rehearsal.
- **A selection outlives its track** against its own doc comment, and the sensor planner's
  recommendation parser turns an unrecognised mode word into "Standby".

None of these is a wrong number on a decision surface. They are the difference between a
console that is correct and one an operator would accept, and each is small.

3. **A row selected in PN-03.** The evidence card opened as a window at the top-left of the

   order applies in draw order, and the focus stroke is the theme's `focus_color` on

## 4. Findings

Severity is against what an operator or a reviewer of a decision surface would accept.

### 4.1 Decision surfaces and safety properties

1. **High. Enter and Space activate a focused Accept.** `decision_dialog.rs:27-29` says
   "No control is bound to Enter, and `render_decision_dialog` returns a choice only from
   a click." The panel binds nothing, but it reads `Response::clicked()`
   (`gungnir-ui/src/panels/decision_dialog.rs:589-597`; the same at
   `control_status_dialog.rs:407-412`). In egui 0.34.3 `clicked()` is true for a focused,
   enabled, click-sensing widget on Enter or Space (`egui/src/response.rs:184`,
   `context.rs:1404`). So once the degraded and rehearsal boxes are ticked, three Tabs from
   the reject-reason field and Enter is an accepted plan. The draw-order property holds and
   nothing requests focus, so the path needs deliberate traversal; the comment claims more
   than the code enforces and no rendered test covers it. `clicked_by(PointerButton::Primary)`
   makes the comment true, if a pointer-only accept is the intended property; the keyboard
   path GAP-224 designs would then be built on purpose rather than inherited.
2. **Medium. A selection outlives its track.** `AppState::selected_track` is documented as
   resolving to `None` once the track is deleted so the card closes
   (`gungnir-app/src/state.rs:519-521`); the accessor returns the raw field
   (`state.rs:1183-1185`) and PN-04 keeps the card open saying the track is no longer in the
   picture (`workspace.rs:1865-1867`). The code wins over the comment; one of them should
   change.
3. **Medium. A silent default in the recommendation parser.** PN-10's recommendation line
   maps the planner's mode word with `_ => SensorMode::Standby`
   (`gungnir-app/src/workspace.rs:927-931`). An unexpected word becomes a recommendation to
   stand a sensor down. The planner's own type should cross the boundary, or the arm should
   refuse.
4. **Medium. Two `Debug` derives would print a passphrase.** `ControlStatusDialogState`
   (`control_status_dialog.rs:49-61`) and `SignInDraft` (`audit.rs:200-210`) derive `Debug`
   over a passphrase field, while `Confirmation` in the same file hand-writes a redacting
   `Debug` and tests it (`control_status_dialog.rs:138-145`). No `{:?}` of either reaches a
   log line today (checked), so this is latent; it is the kind of latent that one
   `tracing::debug!(?dialog)` turns into a finding.
5. **Low. "Never the default" is true in the sense that nothing is pre-chosen.** With no
   degraded condition and no rehearsal sentence, Accept is enabled on a fresh dialog for a
   role with authority; the test at `decision_dialog.rs:683-687` asserts exactly that. The
   wording in the design documents ("never where a habitual click lands") is met by draw
   order alone.

### 4.2 Functional defects

6. **High. The docked replay panel never loads its sessions.** The journal directory is
   read once, when `sessions_read` is false, in `App::draw_docked`
   (`gungnir-app/src/main.rs:630-636`), which only `draw_detached_panel` calls
   (`main.rs:622`). The dock tree draws PN-12 through `PanelBehavior::draw_panel`, whose
   `Replay` arm passes `sustainment.sessions` without reading it (`dock.rs:228-233`). So
   unless the baseline detaches PN-12, the picker is empty for the session, and the
   analyst, intelligence analyst, planner and administrator layouts all dock it
   (`docs/ux/information-architecture.md` §4). The headless tests draw PN-12 with an empty
   list and cannot see this.
7. **Medium. A detached window cannot be closed and cannot be re-docked.**
   `Workspace.detached` is set only from the baseline in `ensure_tree` (`main.rs:504-512`);
   nothing reads `viewport().close_requested()` (no hit in the crate); `show_viewport_immediate`
   runs every frame (`main.rs:536`), so the OS close is undone on the next frame. If the
   backend refuses a second window the closure's `ViewportClass` is discarded
   (`main.rs:536`) and the central panel still says "The viewport is in its own window."
   (`main.rs:797`).
8. **Medium. The alert list is unbounded and has no scroll area.** `AppState.alerts` is
   `Vec<String>` (`state.rs:288`), pushed from 125 sites across 33 files and never
   retained, cleared, drained or truncated (no hit); `render_alert_list` draws every entry
   as a label with no `ScrollArea` (`alerts.rs:55-64`). This is GAP-223's subject with two
   consequences that gap does not name: the panel's cost and height grow with the shift,
   and the docked column clips the oldest.
9. **Medium. Windows open over the strip.** The decision dialog, the control-status dialog
   and the evidence card are `egui::Window`s with no position (`main.rs:686, 745, 780`), so
   egui places them at the top-left, over the strip's first chips. The information
   architecture says the strip is repeated in every window and dialogs open beside the
   queue (`information-architecture.md` §1). A default position below the strip, or an
   anchor to the queue's pane, is the fix.
10. **Medium. Variant names reach the screen.** `approval_queue.rs:494-500` formats a
    withdrawn item with `{layer:?}` and `{status:?}`, bypassing `Vocabulary::layer` and
    `control_status` (D-12); `sensor_management.rs:431-434` prints `SensorMode` with `{:?}`
    beside a `&str`. The crate tests against exactly this elsewhere
    (`sensor_management.rs:505-522`). `approval_queue.rs:333-343` is a second hard-coded copy
    of the layer words.
11. **Medium. A sentence claims a control that is not drawn.** `track_detail.rs:187-197`
    draws "Designation controls are available in this build." when
    `designation_available` is true, and draws no control. The module's own rule is that
    the control is absent rather than inert. The `true` arm is a false claim waiting for a
    flag. In the same file the "Approaches no declared asset" sentence
    (`track_detail.rs:146-153`) is unreachable, because `Section::draw_header` returns
    false for an empty present list (`unavailable.rs:70-73`).
12. **Medium. PN-20 lays out up to 2,000 grid rows a frame and truncates the run log in
    silence.** `audit.rs:360-366` draws `SHOWN_ENTRIES_LIMIT` rows of an earlier segment in
    an `egui::Grid` every frame, the pattern GAP-226 removed from PN-03; the node-segment
    grid at `audit.rs:466-472` has no limit; the run log takes 200 with an unnamed literal
    and says nothing when it drops entries (`audit.rs:804-808`), where the segment view says
    "The newest N of M entries are drawn".
13. **Low. Three unbacked empties.** PN-03 draws "0 tracks, 0 stale" with no reason while
    PN-06 has `EmptyBecause` for the same upstream silence (`track_table.rs:363-370`);
    PN-11's "No gap on the declared approaches to accept." cannot tell no report from no gap
    (`coverage_layers.rs:764-770`, the view has no reason field though its doc says it
    carries one, line 721); PN-08's "No alerts" is drawn from an untyped list that the strip
    itself labels unclassified.

### 4.3 The frame, against §5

14. **High. The glyph instance buffers are re-created on the GPU every frame.**
    `SceneRenderer::paint` calls `set_instances` unconditionally
    (`gungnir-viewport3d/src/gl.rs:137-140`). In three-d 0.19.0 that call allocates fresh
    `InstanceBuffer`s for three transform rows and the colours
    (`three-d/src/renderer/geometry/instanced_mesh.rs:99-108, 124-172`), four buffer
    uploads a frame whether or not any track moved. The struct's doc says both GPU objects
    are "created once" (`gl.rs:79-82`), true of the mesh and not of its instance data. The
    glyph list already rebuilds only on change (`lib.rs:307-309`) and the radius depends only
    on the zoom, so keying the upload on the glyph revision and `meters_per_px` is the whole
    fix.
15. **High. The terrain is re-tessellated every frame.** `draw_terrain_2d` builds two index
    vectors, an id table and an `egui::Mesh` of up to 16,384 projected vertices from the DEM
    on every frame it is drawn (`layers.rs:677-713`), with no key on the view or the
    terrain. The dead-spot texture two hundred lines earlier is the model to copy
    (`layers.rs:470-504`): keyed, decimated, rebuilt on change.
16. **Medium. The picture's layers are reassembled twice a frame.** `draw_picture` recomputes
    coverage circles and the report key, re-projects every hazard and geofence, runs the
    filter predictor over every track at every horizon, and builds the point-cloud and
    dead-spot layers on every frame (`main.rs:810-871`); the same sixty lines are duplicated
    for the detached viewport (`main.rs:555-619`). `prediction::predict` runs a second time
    in PN-04 (`workspace.rs:1886`), and `asset_exposure` scores every track in PN-04, PN-17
    and the warnings tick. PN-10 runs the full `SensorPlanner::recommend` on every frame it
    is visible (`workspace.rs:919`). None of these has a change key; the viewport's own glyph
    rebuild shows the pattern.
17. **Medium. The egui gate times the dock tree only.** `egui_pass_samples` draws
    `tree.ui` (`gungnir-app/tests/frame_budgets.rs:483`); the viewport, the layer assembly
    above, the strip, the card and PN-07 are outside every budget. The `gungnir-ui` row's
    criterion is met at the stated count; the frame an operator sees is the tree plus
    everything the row does not time.
18. **Medium. The 2D path allocates per layer per frame.** Polylines are collected into
    fresh vectors for gaps, predictions, geofences (65 points each), hazards (plus a clone
    of the same polyline at `layers.rs:1069`) and sector outlines; status sentences are
    formatted every frame (`lib.rs:343-348, 401-413`; `layers.rs:562, 1102, 1114`); the plan
    tags do a linear search of the glyphs per solution (`tracks.rs:338`); the binary clones
    the whole glyph vector into the paint callback every frame (`main.rs:900-905`). Point
    clouds are up to 40,000 `circle_filled` shapes a frame (`layers.rs:749-757`). Each is
    small; together they are what the gate would see if it timed the viewport.
19. **Medium. Still blocking the frame thread.** GAP-239's rehearsal run is unchanged
    (`laydown_rehearsal.rs:1183-1192`), and before the spin it builds a throwaway
    `AppState` with its own runtime and journal and ticks a whole recording synchronously
    (`:971-975, 1069-1106, 1129-1138`). New since the last review: the first point-cloud
    registration does `runtime.block_on(GpuContext::new())` on the eframe thread
    (`fusion.rs:115`, from `pointcloud.rs:544`), and `session_summaries` reads every session
    file when PN-12's picker appears (`sustainment.rs:319-330`).
20. **Low. Redraw is a 30 Hz floor, not event-driven.** `request_repaint_after(33 ms)` at
    the end of every frame (`main.rs:25, 349`); a snapshot landing between frames waits for
    the tick. Fine for a console, worth a sentence in `performance-budgets.md`, and the
    reason "power" appears nowhere in `docs/`.
21. **Low. A GL fault in the callback is invisible after the first frame.** `paint` returns
    nothing, checks no GL error, and the crate has no `tracing` call; `main.rs:182-187`
    skips the draw on a poisoned lock, but nothing catches a panic in the callback, so the
    poison can never be observed. §4 asks for a banner.

    virtualisation"**; PN-20's grids (finding 12) are the offline tables.

## 5. What is good, with evidence

- **The view-struct discipline is uniform.** All 23 panels take a borrowed view assembled
  from `AppState`, hold nothing, and return an action enum; exactly one site applies at
  most one action per frame after everything is drawn (`main.rs:327-350`). No statics, no
  `RefCell`, no `ctx.data_mut` store, no reachable `unwrap`, `expect` or `panic` in any of
  the four crates.
- **The honest-state machinery is the strongest thing on the screen.** `Unavailable`,
  `Section`, `EmptyBecause`, `ListOrigin`, `TimeRemaining`, `AlertSummary::Unclassified`,
  a hidden layer named on the map, an unplaceable coverage ring distinguished from an
  uncovered one, a filter that hides everything saying so in the warning colour. On screen
  every absence this review met was explained: the DEM, the designation control, the
  evidence sources, the queue's ordering, the score column.
- **The decision gates are pure, tested predicates** (`accept_enabled`, `override_enabled`,
  `set_enabled`, `draft`) searched exhaustively rather than asserted
  (`decision_dialog.rs:656-708`, `control_status_dialog.rs:481-518`); the passphrase is
  moved out of the dialog state, not copied, and the test proves it.
- **The track table rebuild is the right model for §5**: measured column widths,
  `show_rows`, sort and filter as session state on `AppState`, a test that a thousand
  tracks draw under fifty identifiers, and a gate re-read at the count it claims. The
  dead-spot texture in the viewport is the same discipline applied to a GPU resource.
- **The three-d path is as thin as promised**: everything that decides what is drawn is a
  pure function (`instances`, `camera`, `viewport_from`) with the test that found the
  camera defect before the owner looked; attachment failure is a logged fallback and the
  flags cannot claim a renderer that is not there.
- **The dock is tested as data**: round trip, the detachable list, unknown panel ids, an
  emptied container, mismatched shares. The theme holds every text colour to 4.5:1 on every
  surface in both variants by test, and health is two colours by construction.
- **The render probe closes the gap between "the view struct is right" and "the screen
  says it"**: 175 tests in `gungnir-ui`, 68 of them in `rendered.rs`, plus
  `rendered_workspace.rs` drawing every role.
- **Accessibility carried in shape as well as colour** where it matters most: classification
  frames, hatch, dot and solid dead-spot cells, dashed against solid gaps and hazards.

## 7. Limits

One session on one machine, in a debug build, nobody signed in, the operator layout, four
minutes of a seeded rehearsal; the other seven layouts were seen only through the headless
probe. The three-d scene was looked at here on a display where the owner had already looked;
the GL path remains untested by anything but a person. No usability session was held. The
instanced-mesh and egui findings rest on reading the dependencies' source at the pinned
versions (three-d 0.19.0, egui 0.34.3), not on a profile; timing numbers from this machine
are not reported. The code sweeps were independent reads whose findings were confirmed by
hand; a finding this review does not list was either not found or did not survive that
check.
