# Crate to verification-row map

This is the one table that maps every crate in the workspace to the module name used in
`verification-capability-table.md` and to the status of its verification rows. The
technical layering, dependency graph, and deployment topology are in the workspace
`ARCHITECTURE.md`; the business description of each crate is in
`gungnir-capabilities.md`. This file is deliberately short so it can be kept exact.

The "Table module" column is the value of the *Rust Module* column in
`verification-capability-table.md` §1. Rows in the tracking core have fully specified
oracles and pass criteria. Rows for every other layer are in that table's §2; "Draft"
means the pass criterion is still to be agreed, "Tested" means a unit test of the stated
invariant exists in the crate today, and "Specified" means the criterion is agreed and
the test is the gate.

For §1 rows, "Fully specified" has always meant the criterion and oracle are settled, not
that a test exists. **Gated** is added here for the rows where the differential test now
runs; the date and the measured margin are given so a later tightening can see where the
headroom actually was.

**GAP-067's walk, 2026-09-07.** D-16 agreed every §2 criterion on 2026-09-04; what
remained was confirming, row by row, that the test each row cites actually checks that
criterion. On 2026-09-07 every row below still reading "Tested" was checked against
`verification-capability-table.md` §2 and read as **Specified** without its wording being
rewritten cell by cell, because "Tested" already named the citation checked. What the
owner has confirmed or signed is in [`signatures.md`](signatures.md), not in this table,
and the walk that settled the rest of the rows with a test, on 2026-09-15 and 2026-09-16, is
[`record/2026-09-16/gap-067-walk.md`](record/2026-09-16/gap-067-walk.md). Seven crates carry a row that is
not, in whole or in part: the walk found a wrong citation (corrected in
`verification-capability-table.md` the same day), no test at all, or a criterion nobody
expects to be unit-testable, and each says so in its own cell below rather than being
promoted on the strength of a citation that did not hold up -- `gungnir-tracking-service`,
`gungnir-data-fusion`, `gungnir-render`, `gungnir-viewport3d`, `gungnir-app`,
`gungnir-node`, and `gungnir-decision` all carry the specifics.
