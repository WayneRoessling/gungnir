# GAP-065: the exchange products cross the wire

GAP-065's remaining item, restated earlier the same day, was a byte-for-byte wire check
for warnings, reports and handoffs. GAP-063's suite had covered tracks and health only. It
was written before those three items had producers, and `gungnir-api/tests/exchange.rs`
compared only ids and counts, on placeholder bodies. This item records the check, which
closes GAP-065.

## What the test does

`every_exchange_product_crosses_both_hops_with_zero_loss`, in
`gungnir-remote/tests/wire_conformance.rs`, builds one product of each item the way its
producer does:

- **A launch warning** (`LaunchWarningReport`) with non-ASCII text, as
  `launch_warning::declare` publishes one.
- **A mission report** generated by `JournalReportGenerator` from a real journal of twelve
  corpus tracks, as `sustainment::exchange_record` publishes one. A diverged tracker's
  metrics are added: a NaN MOTA and an infinite MOTP, the two values the "value
  unavailable" encoding exists for.
- **A handoff** (`Handoff::from_decision`) with a full-width decision identifier, an
  intercept solution with its geodetic point, and the provenance of the track it names, as
  the node's approval queue publishes one.

Every body is written through `to_partner_value`, the function both `body_of` and the
desktop's `product_body` call. Each product then crosses both hops:

1. A desktop signed in as a `Commander` writes it to its node through the link
   (`queue_exchange`).
2. A partner reads it from that node over mutual TLS (`GET /v3/exchange/{item}`).

The partner's product must match the desktop's canonical encoding exactly. The body's own
bytes must also appear verbatim in the response the node served, so a transport that
re-encoded consistently on both sides would still be caught. The report's two non-finite
metrics must arrive as DN-18 §15's object, never as `null`.

## What it needed

`gungnir-remote` gains two dev-only dependencies, `gungnir-reporting` and `gungnir-store`,
so the report is generated rather than written by hand. Neither is drawn, per the
convention for dev-only edges. `ARCHITECTURE.md` §7's table row for `gungnir-remote` now
marks them, together with the `gungnir-analytics` dev edge it already had and did not
list.

## Result

It passed the first time it ran: the two hops lose nothing for any produced item. With the
lossy-format half already shown moot (no lossy format can be configured or sent), nothing
of GAP-065 remains, and it closes.
